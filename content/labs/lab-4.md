## 1. ХІД ВИКОНАННЯ РОБОТИ (ПРОГРАМНА РЕАЛІЗАЦІЯ)

Під час виконання лабораторної роботи було створено серверний застосунок на базі Express. Встановлено та налаштовано пакети `morgan` (для логування HTTP-запитів), `winston` (для файлового логування), `multer` (для обробки файлів), а також розгорнуто сервер через менеджер процесів `PM2`.

### 1.1. Головний файл сервера (`app.js`)
У коді реалізовано всі 10 завдань лабораторної роботи: логування, обробка помилок, завантаження та валідація файлів, а також моніторинг ресурсів (час відповіді, пам'ять, uptime).

```javascript
const express = require('express');
const morgan = require('morgan');
const winston = require('winston');
const multer = require('multer');
const fs = require('fs');

const app = express();
const PORT = 3000;

// Створюємо папку uploads автоматично, якщо її немає
if (!fs.existsSync('uploads')){
    fs.mkdirSync('uploads');
}

// ==========================================
// ЛОГУВАННЯ: Winston (Файли та помилки)
// ==========================================
const logger = winston.createLogger({
    level: 'info',
    format: winston.format.combine(
        winston.format.timestamp(),
        winston.format.json()
    ),
    transports: [
        new winston.transports.File({ filename: 'app.log' }),
        new winston.transports.File({ filename: 'error.log', level: 'error' })
    ]
});

// ==========================================
// МОНІТОРИНГ: Вимірювання часу відповіді
// ==========================================
app.use((req, res, next) => {
    const start = Date.now();
    res.on('finish', () => {
        const duration = Date.now() - start;
        logger.info(`[Performance] ${req.method} ${req.url} - ${duration}ms`);
    });
    next();
});

// ЛОГУВАННЯ: Morgan (HTTP-запити у консоль)
app.use(morgan('dev'));

// ==========================================
// ЗАВАНТАЖЕННЯ ФАЙЛІВ: Налаштування Multer
// ==========================================
const storage = multer.diskStorage({
    destination: (req, file, cb) => {
        cb(null, 'uploads/');
    },
    filename: (req, file, cb) => {
        cb(null, Date.now() + '-' + file.originalname);
    }
});

const fileFilter = (req, file, cb) => {
    const allowedTypes = ['image/jpeg', 'image/png', 'application/pdf'];
    if (allowedTypes.includes(file.mimetype)) {
        cb(null, true);
    } else {
        cb(new Error('Неправильний формат файлу. Дозволено лише JPG, PNG, PDF'), false);
    }
};

const upload = multer({ 
    storage: storage,
    limits: { fileSize: 1024 * 1024 * 2 }, // Обмеження: 2MB
    fileFilter: fileFilter 
});

// ==========================================
// МАРШРУТИ
// ==========================================

app.get('/', (req, res) => {
    logger.info('Відвідування головної сторінки');
    res.send('Server is running. Ласкаво просимо до ЛР №4!');
});

// Завантаження одного файлу
app.post('/upload', upload.single('file'), (req, res) => {
    res.json({ message: 'Файл успішно завантажено', file: req.file });
});

// Завантаження кількох файлів (макс 5)
app.post('/upload-multiple', upload.array('files', 5), (req, res) => {
    res.json({ message: 'Файли успішно завантажено', files: req.files });
});

// Моніторинг стану сервера (Uptime та Пам'ять)
app.get('/status', (req, res) => {
    const memory = process.memoryUsage();
    const uptime = process.uptime();
    
    res.json({
        message: "Статус сервера",
        uptime_seconds: Math.round(uptime),
        memoryUsage: {
            rss: `${Math.round(memory.rss / 1024 / 1024)} MB`,
            heapTotal: `${Math.round(memory.heapTotal / 1024 / 1024)} MB`,
            heapUsed: `${Math.round(memory.heapUsed / 1024 / 1024)} MB`
        }
    });
});

// Тестовий маршрут для перевірки глобальної обробки помилок
app.get('/error-test', (req, res) => {
    throw new Error('Штучна критична помилка для тестування Winston!');
});

// ==========================================
// ГЛОБАЛЬНА ОБРОБКА ПОМИЛОК
// ==========================================
app.use((err, req, res, next) => {
    logger.error(`Помилка: ${err.message} - URL: ${req.url}`);
    res.status(500).json({ error: "Внутрішня помилка сервера", message: err.message });
});

app.listen(PORT, () => {
    console.log(`🚀 Сервер запущено на порту ${PORT}`);
    logger.info(`Сервер запущено на порту ${PORT}`);
});

```

## 2. ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ

**1. Що таке middleware у Node.js?**
Middleware — це проміжна функція, яка має доступ до об'єкта запиту (`req`), об'єкта відповіді (`res`) та наступної функції (`next`) в циклі обробки. Middleware використовується для перехоплення запиту ДО того, як він дійде до кінцевого обробника. Наприклад, для перевірки авторизації, логування, парсингу файлів або вимірювання часу виконання.

**2. Яка різниця між Morgan і Winston?**
`Morgan` — це вузькоспеціалізований інструмент виключно для логування HTTP-запитів. Він автоматично виводить у консоль інформацію про те, який метод, шлях, статус та за який час був оброблений.
`Winston` — це професійна та гнучка система логування. Вона дозволяє фіксувати будь-які події у програмі (помилки, дії користувачів, старти БД), розподіляти їх за рівнями важливості (`info`, `error`, `warn`) та зберігати у зовнішні файли або бази даних у форматі JSON.

**3. Як працює Multer?**
Multer — це middleware для обробки даних формату `multipart/form-data`, який використовується під час завантаження файлів з HTML-форм або клієнтів (Postman). Коли файл надходить на сервер, Multer перехоплює запит, читає файл, зберігає його в задану папку на диску (або в пам'ять), присвоює йому ім'я та генерує об'єкт `req.file` з усіма метаданими (розмір, тип, шлях). Лише після цього управління передається основному коду розробника.

**4. Які метрики продуктивності важливі для серверів?**
Основними метриками є:

* **Час відповіді сервера (Response Time):** час, за який сервер повністю обробляє запит клієнта.
* **Використання пам'яті (Memory Usage):** кількість оперативної пам'яті, зайнятої процесом (`rss`, `heapUsed`). Допомагає виявляти витоки пам'яті.
* **Навантаження на процесор (CPU Load):** показує, наскільки процесор зайнятий обчисленнями.
* **Uptime:** показник стабільності, час безперервної роботи системи.

**5. Що таке uptime?**
Uptime — це час (зазвичай у секундах, годинах або днях), протягом якого сервер або конкретний процес (застосунок) працює безперервно з моменту останнього запуску або перезавантаження.

## ВИСНОВКИ

Під час виконання лабораторної роботи було успішно досліджено розширені можливості платформи Node.js для створення професійних backend-застосунків. На практиці було інтегровано систему комплексного логування, де `Morgan` фіксує всі HTTP-запити, а `Winston` структурує події та помилки у зовнішні JSON-файли для подальшого аналізу.

За допомогою middleware `Multer` було реалізовано безпечне завантаження як одиничних, так і множинних файлів із використанням фільтрації за MIME-типом та обмеженням розміру, що захищає сервер від шкідливих файлів. Крім того, розроблено механізми моніторингу продуктивності для відстеження використання оперативної пам'яті (`process.memoryUsage`), часу життя сервера (`uptime`) та часу обробки запитів. Інтеграція застосунку з менеджером процесів `PM2` забезпечила автоматичний контроль за стабільністю сервера та зручний графічний моніторинг навантаження в реальному часі.
