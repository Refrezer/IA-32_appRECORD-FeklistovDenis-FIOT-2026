### 1.1. Головний файл сервера (`server.js`)
Реалізовано захищені маршрути з механізмами валідації та кешування, що дозволяє суттєво зменшити час відповіді при повторних запитах.

```javascript
const express = require('express');
const helmet = require('helmet');
const rateLimit = require('express-rate-limit');
const { body, validationResult } = require('express-validator');
const NodeCache = require('node-cache');

const app = express();
// Кеш із часом життя 60 секунд
const cache = new NodeCache({ stdTTL: 60 }); 

app.use(express.json());
app.use(helmet()); 

// Захист від DDoS: 10 запитів на хвилину
const limiter = rateLimit({
    windowMs: 1 * 60 * 1000, 
    max: 10
});
app.use(limiter);

const products = [
    { id: 1, name: "Laptop", price: 30000 },
    { id: 2, name: "Phone", price: 20000 }
];

app.get('/products', (req, res) => {
    const cached = cache.get('products');
    
    if (cached) {
        return res.json({    
            source: 'cache',
            data: cached
        });
    }    
    
    cache.set('products', products);
    res.json({
        source: 'database',
        data: products
    });
});

app.post(
    '/products',
    body('name').isLength({ min: 3 }),
    body('price').isNumeric(),
    (req, res) => {
        const errors = validationResult(req);  
        if (!errors.isEmpty()) {
            return res.status(400).json(errors.array());
        }        
        
        const product = {
            id: products.length + 1,
            name: req.body.name,
            price: req.body.price
        };
        products.push(product);        
        
        cache.del('products');        
        res.status(201).json(product);
    }
);

app.listen(3000, () => {
    console.log('Server started on port 3000');
});

```

## 3. ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ

**1. Що таке Helmet у Node.js?**
Helmet — це middleware для Express, який автоматично налаштовує безпечні HTTP-заголовки. Він захищає застосунок від низки відомих веб-вразливостей (наприклад, приховує заголовок `X-Powered-By`, запобігає Clickjacking атакам через `X-Frame-Options` тощо).

**2. Для чого використовується rate limiting?**
Rate limiting (обмеження частоти запитів) використовується для захисту сервера від великої кількості запитів (DDoS-атак) та атак типу Brute Force (підбір паролів). Він блокує IP-адреси клієнтів, які перевищують дозволений ліміт звернень за певний проміжок часу.

**3. Які переваги кешування?**
Кешування зменшує навантаження на базу даних та сервер, значно пришвидшує час відповіді для клієнта (завдяки видачі даних з оперативної пам'яті) та покращує загальну масштабованість додатку .

**4. Чим відрізняється unit testing від integration testing?**
Unit testing (модульне тестування) ізольовано перевіряє роботу окремих найменших частин коду (функцій, класів). Integration testing (інтеграційне тестування) перевіряє, як ці окремі компоненти працюють разом (наприклад, як контролер взаємодіє з базою даних).

**5. Для чого потрібна валідація даних?**
Валідація потрібна для перевірки даних, які надсилає користувач. Вона гарантує, що сервер отримає дані у правильному форматі, та захищає базу даних від запису "сміття", а також від SQL/NoSQL ін'єкцій та XSS атак.

**6. Що таке JWT?**
JWT (JSON Web Token) — це відкритий стандарт для безпечної передачі інформації між клієнтом і сервером у вигляді JSON-об'єкта. У серверних застосунках використовується для безпечної автентифікації та авторизації без необхідності зберігати стан сесії на сервері.

**7. Які типи кешування існують?**
Існують такі основні види кешування: In-memory cache (кешування в оперативній пам'яті сервера, наприклад, `node-cache`), розподілене кешування (Redis), CDN cache (кешування статики на серверах провайдера контенту) та browser cache (кешування на стороні браузера клієнта) .

**8. Які існують способи оптимізації API?**
До основних підходів оптимізації належать: пагінація (видача даних частинами), кешування, індексація бази даних, асинхронна обробка важких завдань, стиснення відповідей (наприклад, gzip) та оптимізація SQL/NoSQL-запитів .
