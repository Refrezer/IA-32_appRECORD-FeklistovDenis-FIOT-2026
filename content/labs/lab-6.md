## 1. ХІД ВИКОНАННЯ РОБОТИ (ПРОГРАМНА РЕАЛІЗАЦІЯ)

Під час виконання підсумкової лабораторної роботи було створено повноцінний REST API застосунок для керування користувачами. Як базу даних було успішно підключено локальний сервер MySQL з використанням ORM Sequelize. 

Для документування API було інтегровано інструментарій Swagger (пакети `swagger-ui-express` та `swagger-jsdoc`). Щоб уникнути проблем із форматуванням синтаксису YAML під час автоматичного збереження файлів, конфігурацію OpenAPI специфікації та опис маршрутів було реалізовано безпосередньо через JavaScript-об'єкти (JSON).

### 1.1. Головний файл сервера (`app.js`) з інтеграцією MySQL та Swagger
У коді реалізовано підключення до БД, налаштування документації OpenAPI та базові CRUD-операції (`GET`, `POST`, `DELETE`).

```javascript
const express = require('express');
const swaggerUi = require('swagger-ui-express');
const swaggerJsdoc = require('swagger-jsdoc');
const { Sequelize, DataTypes } = require('sequelize');

const app = express();
app.use(express.json());

// ==========================================
// 1. БАЗА ДАНИХ MYSQL 
// ==========================================
const sequelize = new Sequelize({
    database: 'lab6_db',
    username: 'root',
    password: '***', // Приховано з міркувань безпеки
    host: 'localhost',
    dialect: 'mysql',
    logging: false
});

const User = sequelize.define('User', {
    name: { type: DataTypes.STRING, allowNull: false },
    email: { type: DataTypes.STRING, allowNull: false }
});

// ==========================================
// 2. НАЛАШТУВАННЯ SWAGGER
// ==========================================
const swaggerOptions = {
    definition: {
        openapi: '3.0.0',
        info: {
            title: 'Users CRUD API',
            version: '1.0.0',
            description: 'API документація для керування користувачами (ЛР №6)',
        },
        servers: [{ url: 'http://localhost:3000' }],
        paths: {
            '/users': {
                get: {
                    summary: 'Отримати список всіх користувачів',
                    responses: { '200': { description: 'Успішна відповідь' } }
                },
                post: {
                    summary: 'Створити нового користувача',
                    requestBody: {
                        required: true,
                        content: {
                            'application/json': {
                                schema: {
                                    type: 'object',
                                    properties: {
                                        name: { type: 'string' },
                                        email: { type: 'string' }
                                    }
                                }
                            }
                        }
                    },
                    responses: { '201': { description: 'Користувача створено' } }
                }
            },
            '/users/{id}': {
                delete: {
                    summary: 'Видалити користувача за ID',
                    parameters: [{
                        in: 'path',
                        name: 'id',
                        required: true,
                        schema: { type: 'integer' },
                        description: 'ID користувача'
                    }],
                    responses: { '200': { description: 'Користувача видалено' } }
                }
            }
        }
    },
    apis: [],
};

const swaggerSpec = swaggerJsdoc(swaggerOptions);
app.use('/api-docs', swaggerUi.serve, swaggerUi.setup(swaggerSpec));

// ==========================================
// 3. МАРШРУТИ
// ==========================================
app.get('/users', async (req, res) => {
    const users = await User.findAll();
    res.json(users);
});

app.post('/users', async (req, res) => {
    const user = await User.create(req.body);
    res.status(201).json(user);
});

app.delete('/users/:id', async (req, res) => {
    await User.destroy({ where: { id: req.params.id } });
    res.json({ message: 'Користувача видалено' });
});

// ==========================================
// 4. ЗАПУСК СЕРВЕРА
// ==========================================
const PORT = process.env.PORT || 3000;
sequelize.sync({ alter: true }).then(() => {
    app.listen(PORT, () => {
        console.log(`🚀 Сервер працює: http://localhost:${PORT}`);
        console.log(`📄 Документація Swagger: http://localhost:${PORT}/api-docs`);
    });
});

```

## 4. ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ

**1. Що таке REST API?**
REST API (Representational State Transfer) — це архітектурний стиль взаємодії компонентів розподіленого додатку в мережі. Він базується на використанні стандартних HTTP-методів для доступу та маніпуляції даними (ресурсами), які найчастіше передаються у форматі JSON .

**2. Для чого використовується Swagger?**
Swagger — це набір інструментів для автоматизованого документування та зручного тестування REST API. Він дозволяє розробникам та клієнтам розуміти структуру API без необхідності вивчати вихідний код .

**3. Що таке OpenAPI?**
OpenAPI Specification (OAS) — це універсальний стандарт (формат) опису REST API, на якому базується Swagger. Він стандартизує опис маршрутів, параметрів, форматів відповідей та авторизації .

**4. Які HTTP-методи використовуються у REST?**
Основні методи: `GET` (отримання даних), `POST` (створення), `PUT` (повне оновлення), `PATCH` (часткове оновлення) та `DELETE` (видалення) .

**5. Для чого потрібен swagger-jsdoc?**
Пакет `swagger-jsdoc` використовується для генерації офіційної специфікації OpenAPI безпосередньо з коментарів у коді розробника або з конфігураційних JavaScript/JSON об'єктів.

**6. Що таке endpoint?**
Endpoint — це конкретна кінцева точка доступу до сервісу. Це комбінація URL-адреси (шляху) та HTTP-методу (наприклад, `GET /users` або `POST /users`), яка виконує специфічну дію .

**7. Які переваги Swagger UI?**
Swagger UI надає зручний графічний веб-інтерфейс, який дозволяє візуально переглядати всі наявні endpoints, досліджувати їхні параметри та моделі даних, а також відправляти реальні HTTP-запити до сервера (тестувати) прямо з браузера без використання сторонніх програм на кшталт Postman .

**8. Для чого використовується Express.js?**
Express.js — це швидкий та мінімалістичний веб-фреймворк для Node.js, який використовується для створення веб-серверів, налаштування маршрутизації (routing) та обробки HTTP-запитів і відповідей.

**9. Що таке деплой?**
Деплой (Deployment) — це процес розгортання та публікації програмного забезпечення на віддаленому сервері (VPS) або хмарній платформі (Render, AWS, Heroku). Після успішного деплою застосунок стає доступним в мережі Інтернет 24/7 .

**10. Для чого потрібен GitHub під час деплою?**
GitHub виступає як єдине надійне джерело коду (Source of Truth). Сучасні платформи деплою (наприклад, Render) підключаються до репозиторію на GitHub і автоматично оновлюють сервер кожного разу, коли розробник відправляє (push) нові зміни у гілку, реалізуючи таким чином процес безперервної інтеграції (CI/CD) .
